## 3. 수행한 작업

### 3.1 데이터 탐색 (01)
- count matrix 구조 확인: 행 = 유전자(Ensembl ID), 열 = 샘플
- **62,703개 유전자 중 30,764개(약 49%)가 모든 샘플에서 count 0** → 필터링 필요성 발견
- 샘플별 library size 비교: 15,776,874 ~ 24,613,552 reads (최대 약 1.56배 차이) → 정규화 필요성 확인
- log2 분포, 샘플 상관관계 heatmap, PCA, 유전자 검출률 분석 코드 작성

### 3.2 정규화 이론 정리와 QC (02)
- CPM, RPKM/FPKM, TPM, TMM, DESeq2(median of ratios) 다섯 가지 방법을 **보정 대상, 장단점, 사용 상황** 기준으로 비교표 작성
- 핵심 원칙 정리: *"DE 분석에는 raw count를 쓰고, 정규화는 DE 도구 내부에서 처리한다"*
- CPM, log2 CPM 정규화 적용과 정규화 전후 분포 비교

### 3.3 이번에 새롭게 한 것 (2026-11-09)

| 구분 | 내용 | 왜 필요했나 |
|---|---|---|
| **샘플 매칭 수정** | `metadata.csv`를 실제 count 컬럼 이름(`...-HepG2-C1_S7` 등) 기준으로 재작성하고, `label`, `replicate` 컬럼 추가 | 기존에는 조건 라벨을 손으로 리스트에 적어 넣어서, 컬럼 순서가 바뀌면 라벨이 조용히 틀어질 위험이 있었음 |
| **안전장치** | metadata에 없는 샘플이 있으면 에러를 내고, 샘플 이름 코드(C/W/L)와 condition이 일치하는지 검증 | 샘플 라벨 오류는 분석 전체를 무효로 만드는 가장 치명적인 실수 |
| **저발현 유전자 필터링** | CPM ≥ 1인 샘플이 3개 이상인 유전자만 유지 (3 = 가장 작은 그룹 크기) | noise 감소, 다중검정 부담 감소. 한 조건에서만 발현되는 유전자도 남도록 기준 설계 |
| **필터링 후 QC** | 변동이 큰 상위 500개 유전자로 PCA, 샘플 상관관계 heatmap | replicate끼리 묶이는지, outlier가 있는지 확인 |
| **차등 발현 분석 (03)** | `pydeseq2`로 DESeq2 모델을 9개 샘플 전체로 fitting하고 세 가지 비교 수행 | 아래 표 참고 |
| **비교 분석** | Welch t-test(log2 CPM) + Benjamini–Hochberg FDR 결과와 DESeq2 결과의 DEG 겹침 비교 | 원래 계획(t-test)과 표준 방법(DESeq2)의 차이를 직접 확인 |
| **시각화** | 비교별 volcano plot, MA plot | DEG 분포와 발현량에 따른 fold change 확인 |
| **코드 모듈화** | `src/normalization.py`, `src/stats.py`, `src/plotting.py` | 노트북 간 중복 제거, 재사용성과 가독성 향상 |
| **버그 수정** | 저장 폴더 자동 생성, matplotlib 최신 버전의 `boxplot(tick_labels=)` 대응 | 노트북이 처음부터 끝까지 에러 없이 실행되도록 |

세 가지 비교와 각각의 질문:

| 비교 | 묻는 질문 |
|---|---|
| WT vs control | SIRT6를 과발현하는 것 자체의 효과는? |
| variant vs control | 장수 변이 SIRT6의 효과는? |
| **variant vs WT** | 변이가 WT와 *다르게* 하는 것은? → **이 연구의 핵심 질문** |

DEG 기준: adjusted p-value < 0.05 그리고 |log2 fold change| > 1

## 4. 검증

실제 count 파일(`counts_matrix.tsv`)은 용량 때문에 Git에서 제외되어 있어, 실제 샘플 이름과 같은 형식의 **합성 데이터**(일부 유전자에 의도적으로 발현 차이를 심어둔 데이터)로 01 → 02 → 03 노트북을 처음부터 끝까지 실행해 검증했다.

- 세 노트북 모두 에러 없이 실행됨
- DESeq2가 심어둔 차등 발현 유전자를 잘 찾아냄
- 같은 데이터에서 t-test는 비교별 DEG를 2~11개밖에 찾지 못함 → **그룹당 반복이 3개뿐일 때 t-test의 검정력이 매우 낮다**는 점을 직접 확인했고, DESeq2를 메인 방법으로 선택한 근거가 됨

> ⚠️ 위 숫자는 파이프라인 검증용 합성 데이터 결과이며, **실제 생물학적 결과가 아니다.** 실제 DEG 결과는 진짜 데이터로 실행한 뒤 `reports/analysis_summary.md`에 정리할 예정.

## 6. 배운 점

**생물정보학 / 통계**
- RNA-seq count는 **library size, 유전자 길이, RNA composition** 세 가지 기술적 편향을 가지며, 목적에 따라 정규화 방법이 달라야 한다. (시각화: CPM/TPM, DE 분석: TMM/DESeq2)
- DE 분석에는 정규화된 값이 아니라 **raw count**를 넣어야 한다. 정규화는 모델 내부에서 처리된다.
- 수만 개 유전자를 동시에 검정하면 우연히 유의한 결과가 많이 나오므로 **다중검정 보정(BH FDR)** 이 필수다.
- 표본이 작을 때는 단순 t-test보다 **유전자 간 정보를 공유하는 모델(DESeq2)** 이 훨씬 안정적이다. 합성 데이터 실험으로 그 차이를 직접 확인했다.
- 저발현 유전자 필터링 기준은 임의의 숫자가 아니라 **실험 설계(그룹 크기)** 에 맞춰 정해야 한다.
- 비교 설계(contrast)가 곧 연구 질문이다. "variant vs WT"처럼 무엇과 무엇을 비교하느냐가 답할 수 있는 질문을 결정한다.

**재현 가능한 분석 / 엔지니어링**
- 샘플 라벨을 손으로 적는 방식은 위험하다. **이름으로 매칭하고, 어긋나면 바로 에러를 내는** 방식이 안전하다.
- 노트북 실행 순서가 섞이면 결과를 믿기 어렵다. 커널 재시작 후 **Run All로 처음부터 끝까지 돌아가야** 재현 가능하다.
- 반복되는 코드는 `src/` 모듈로 분리하면 노트북은 "분석 흐름"에, 모듈은 "구현"에 집중할 수 있다.
- 실제 데이터 없이도 **결과를 알고 있는 합성 데이터**로 파이프라인이 맞게 동작하는지 검증할 수 있다.
- 오래 쉰 프로젝트는 먼저 현재 상태를 진단하고 할 일 목록을 만드는 것이 재개의 가장 빠른 길이다.
